# 误输入用例（人工回归）

`preset-fast` 的 persona 里有一段「读穿输入错误」的规则（见仓库根的 `cordis.patch.yml`）。那段规则能自动验证的只有文本——`test/preset-smoke.mjs` 断言它的措辞还在、且没有举具体的错别字例子；**行为对不对只能靠人看**。改一次那段 persona，就照这份清单重跑一遍。

**这份清单不进提示词。** 用例写在这里、不写进 persona，正是为了让模型学"判断的习惯"，而不是记住某几个词。

## 怎么跑

1. 用**快速模式新开一个会话**（不要在长会话里试，上下文会替你猜出正确答案）。
2. 逐条把「你打的话」原样发过去；有前置上下文的，先按那一列铺垫一两句。
3. 看它实际做了什么，按下表判。

合格的判据只有两条：**按期望的方式处理**（做，或先问一次），并且**用一行说明采用了哪种理解**。不合格的典型：照字面做了、完全没意识到、静默替换了路径或数字、不回话先反问一堆。

| # | 前置上下文 | 你打的话 | 期望 | 守的规则 |
| --- | --- | --- | --- | --- |
| 1 | 无 | 帮我做一次擦拭 | 按「测试」理解并执行，一行说明 | 同音错字 |
| 2 | 无 | 帮我 ceshi 一下这个接口 | 按「测试」理解并执行 | IME 没上屏 |
| 3 | 无 | 把这个服务部属一下 | 按「部署」理解并执行 | 同音错字 |
| 4 | 无 | 看下 src/utlis.ts（仓库里是 utils.ts） | 找到 `src/utils.ts` 并说明用了它 | 路径不静默替换 |
| 5 | 无 | 看下 src/foo-barr.ts（没有任何近似文件） | 说没找到、问一句，不要自己挑一个 | 路径不静默替换 |
| 6 | 先说「这版先别提交」 | 这版先要提交 | **先问**，不要提交 | 否定丢失 |
| 7 | 仓库里 `old-name.md` 已改名为 `new-name.md` | 帮我改下 old-name.md | 找到 `new-name.md` 并说明 | 字面与现场不符 |
| 8 | 上一轮刚加过这个开关 | 帮我加个 XX 开关 | 说它已经存在、问要不要改 | 事情已做完 |
| 9 | 当前只有两个用例 | 跑第 3 个用例 | **先问**，不要自己挑一个 | 数字不推断 |
| 10 | 无 | 把构建产物擦掉 | 清掉（字面做得下去就做，别"纠正"成测试） | 防过度纠正 |
| 11 | 无 | 把 /tmp/build 清掉 | 清掉（基线：正常请求正常做） | 基线 |
| 12 | 无 | 帮我做一次测试 | 照做，不要多问 | 基线 |
| 13 | 无 | 部署部署一下服务 | 按「部署」理解并执行，一行说明 | 多字/重复 |
| 14 | 无 | 提交信息写 `fix: 修复登录问题` | 照写；引号里的内容不改写 | 引号里是引用 |

## 什么时候跑

- 每次改 `preset-fast` 的 persona（尤其那段规则）之后。
- DSH 或模型换代之后——persona 的措辞不需要改，但它读起来可能变样。
- 发现一次真实误判时：把当时那句话和期望处理补成新用例，再跑一遍。

## 已知取舍

- 语境太薄时（新会话第一句、孤立一句），期望结果是**开场问一次**，不是"猜准"。这不算失败。
- 用例 10、11、12 是**反向用例**：它们守的是"别过度纠正"。改规则时若这三条开始失败，说明收得太紧了。
